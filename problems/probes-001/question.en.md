Today its Pods restart repeatedly and never become Ready, so the Service has no endpoints.

Fix the probes of container `web` on the existing Deployment: the readiness probe is an HTTP GET on `/ready` and the liveness probe is an HTTP GET on `/healthz`, both against the port the application really listens on; add a startup probe, an HTTP GET on `/healthz`, that tolerates the roughly 10-second startup. Do not change the image or the command, and do not remove the probes. Both replicas must become Ready and stay Ready without restarts, and Service `checkout` must serve the application.

Each group earns 1 point: the readiness probe path `/ready`; the liveness probe path `/healthz`; the startup probe path `/healthz`; both replicas stable (Ready and Available, no restarts, for the 15-second stability window within the 90-second observation limit); and an HTTP 200 body containing `checkout-ok` through Service `checkout` port 80 (60-second limit).
