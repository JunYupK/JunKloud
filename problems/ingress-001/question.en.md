Deployments `shop-web` and `shop-api` and Services `shop-web` and `shop-api` already exist in `${namespace}`. Each Service has the port `80` and forwards it to port `8080` of the Pods of the Deployment with the same name. `shop-web` answers `web-ok` and `shop-api` answers `api-ok`, both on the path `/api/` (and `shop-web` also on `/`). Nothing exposes them through an Ingress yet.

Create Ingress `shop` in `${namespace}` with the IngressClass `cloud-provider-kind` (`spec.ingressClassName`). The default IngressClass of the cluster is `cloud-provider-kind`, which the API server sets on an Ingress that names no class, so leaving `spec.ingressClassName` out ends in the same Ingress; any other class is not served by a controller of this environment. It has two hosts, and every path uses the pathType `Prefix` and a backend on port `80` of the Service. Host `shop.${namespace}.example` sends the path `/` to Service `shop-web` and the path `/api` to Service `shop-api`. Host `api.${namespace}.example` sends the path `/` to Service `shop-api`. The host names resolve nowhere: the checks put them in the `Host` header of their requests, so the rule that matches the `Host` and the path decides which Service answers.

Each of the following earns 1 point: Deployment `shop-web` has 1 Ready replica (10-second stability window, 90-second observation limit); Deployment `shop-api` has 1 Ready replica (10-second stability window, 90-second observation limit); a request through Ingress `shop` with the `Host` `shop.${namespace}.example` and the path `/` returns HTTP 200 with a body containing `web-ok` (60-second limit; this point needs the first one); a request through Ingress `shop` with the `Host` `shop.${namespace}.example` and the path `/api/` returns HTTP 200 with a body containing `api-ok` (60-second limit; this point needs the second one); a request through Ingress `shop` with the `Host` `api.${namespace}.example` and the path `/api/` returns HTTP 200 with a body containing `api-ok` (60-second limit; this point needs the second one); and Ingress `shop` has `spec.ingressClassName` `cloud-provider-kind` and a rule for each of the hosts `shop.${namespace}.example` and `api.${namespace}.example`. Each request is sent to the address that the Ingress controller assigns to Ingress `shop`, and the check waits up to 15 seconds for that address. A Service that answers HTTP 200 with the wrong body loses the point, because the body shows which application answered; a rule without a host or a default backend does not replace the rule of a host.
