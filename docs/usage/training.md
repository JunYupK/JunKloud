# 훈련 흐름 안내

연습(훈련)과 모의시험의 전체 흐름, 채점, 복습, 초기화, 오답 재도전, 오류 복구를 명령 단위로 정리합니다. 처음이라면 [README](../../README.md)의 1~7장을 먼저 따라 하세요. 모든 명령은 **작업 컨테이너 안**에서 실행합니다. 이 문서의 명령과 옵션은 `ckad --help`와 각 하위 명령의 `--help` 출력과 맞춰 확인했습니다.

## 1. 모드 비교

| 기능 | 모의시험 (`ckad start`) | 훈련 (`ckad start --mode practice`) |
| --- | --- | --- |
| 구성 | `mock-01`: 20문제, 120분, 100점 | 5~20문제, 필터 지원 |
| 문제별 채점 | 불가. 전체 제출만 | 가능 (`ckad grade --problem Q1`) |
| 실패 원인 공개 | 제출(채점) 후 | 채점 요청 시 |
| 해설·모범 풀이 | 전체 제출을 오류 없이 채점한 뒤 열람 | 사용자가 `--solution`으로 직접 열람 |
| 문제 하나 reset | 진행 중에는 불가 | 가능 (`ckad reset --problem Q1`) |
| 시작 조건 | 20문제 모두 출제 가능해야 함 | 검증된 문제가 요청 수 이상이면 됨 |

## 2. 훈련 (practice)

```sh
ckad list
ckad start --mode practice --count 5
```

- 선택 옵션: `--count`(5~20, 기본 5), `--domain`(`design-build`, `deployment`, `observability`, `environment-security`, `networking`), `--difficulty`, `--tag`, `--seed`(같은 선택 재현).
- 준비가 끝나면 `준비 완료: ... 시작하시겠습니까? [yes/no]:`가 나옵니다. `yes`(또는 `y`, `예`)를 입력하면 시계가 시작되고 `학습 시작: <세션 ID>`가 나옵니다. 그 외 입력이나 이 확인 질문에서의 중단(`Ctrl+C`, 터미널 종료)이면 준비가 끝난 상태가 보존되며, 인자 없는 `ckad start`로 확인을 다시 할 수 있습니다. 이 상태에서 인자나 옵션을 준 `ckad start`(예: `--mode mock`, `--count 10`, `mock-01`)는 옛 세션을 다시 내놓지 않고 종료 코드 2로 거부하며 인자 없는 `ckad start` 또는 `ckad reset`을 안내합니다.
- **준비가 실패한 뒤**(`ckad status`가 `준비에 실패했습니다...`, SETUP_ERROR)의 `ckad start`는 인자와 상관없이 `이전 준비가 완료되지 못했습니다(세션 <ID>). ckad reset으로 정리한 뒤 다시 시작하세요.`와 종료 코드 2로 끝납니다. `ckad reset` 후 다시 시작하세요.
- **준비 중**(확인 질문이 나오기 전)의 중단은 이어지지 않습니다. `Ctrl+C`이면 `ckad status`가 `준비에 실패했습니다...`, 프로세스가 강제로 끊기면(kill, 재부팅) `이전 준비가 중단되었습니다...`라고 알리고 둘 다 종료 코드 3입니다. `ckad reset`으로 정리한 뒤 `ckad start`를 처음부터 다시 하세요(9장).
- 문제 본문과 제공 파일은 시작 확인 뒤에 공개됩니다.

## 3. 모의시험 (mock)

```sh
ckad start               # mock-01
ckad start mock-01       # 같은 시험을 ID로 지정
```

- 모의시험은 고정 구성이라 `--count`와 필터를 쓰면 `모의시험은 고정 구성입니다. 필터와 --count는 --mode practice에서 사용하세요.`(종료 코드 2)로 거부됩니다.
- 20문제 중 하나라도 출제할 수 없으면 시험 전체를 거부합니다(종료 코드 3, 세션 없음). 문제를 몰래 바꾸거나 빼지 않습니다. `ckad list`의 `출제 불가:` 줄과 `ckad doctor`로 원인을 봅니다.
- `network-policy`가 FAIL인 호스트는 `networkpolicy-001`을 낼 수 없어 모의시험이 거부됩니다. 이 호스트에서는 훈련 모드를 쓰세요.
- 시계는 터미널을 닫거나 컴퓨터가 잠들어도 흐릅니다. 제한 시간을 넘겨도 제출은 가능하며 초과 시간이 표시됩니다.
- 66% 기준은 참고용입니다.

## 4. 문제 읽기와 풀기

```sh
ckad status            # 세션, 모드, 상태, 경과·초과·제한 시간, 문제 목록(Q1...), 미완료 작업 (중단·실패한 준비는 종료 코드 3)
ckad show Q1           # 영어 문제, Context, Namespace, 제공 파일 이름과 내용
ckad mark Q3 --review  # 다시 볼 문제 표시 (채점에 영향 없음)
ckad mark Q3 --clear   # 표시 해제
```

- 풀이 폴더: `~/ckad/<세션 ID>/<문제 ID>/attempt-<n>/`. 이 폴더에 `question.md`와 제공 파일이 있습니다.
- `kubectl`/`k`는 전용 클러스터의 kubeconfig를 자동으로 씁니다. 문제 namespace는 `ckad show`에 나온 값을 사용하세요.
- 이미지 문제는 [README 7장](../../README.md#7-이미지-빌드-문제)을 보세요.

## 5. 채점

```sh
ckad grade --problem Q1    # 훈련: 문제 하나
ckad grade                 # 세션 전체 제출 (모의시험은 이것만 가능)
```

- 채점 중에는 답안을 수정하지 마세요. 대상이 바뀐 것이 감지되면 결과를 확정하지 않습니다.
- 출력: `채점 실행: ...`, 확정되면 `점수: N/M`, 이어서 `요구사항 <문제 ID>/<항목 ID>: PASS|FAIL|ERROR (N점)`. FAIL에는 기대·관찰·한국어 피드백·관찰 근거가, ERROR에는 `ckad doctor`로 확인하라는 안내가 붙습니다. ERROR가 있으면 `채점 미완료: 확정 총점 없음`이 나옵니다.
- 모의시험 전체 제출 후에는 `참고 기준: 66% | 이번 비율: ...`도 표시됩니다.
- 종료 코드: 0 만점(또는 확정된 기존 결과 재표시), 1 정상 채점이나 미충족, 2 사용법·모드 오류, 3 환경·저장·채점 불가(ERROR 포함. ERROR·미완료 결과를 `ckad grade`로 다시 보여 줄 때도 3).

### 다시 채점: `--retry` / `--resubmit`

진행 중인 훈련에서 문제 하나를 채점한 경우:

| 상황 | 명령 |
| --- | --- |
| 그 문제가 ERROR이고 답안은 그대로다 | `ckad grade --problem Q1 --retry` (같은 제출을 다시 관찰. 새 grading run으로 기록) |
| 답안을 고쳤다 | `ckad grade --problem Q1` (답안이 바뀐 것을 확인하면 새 제출로 기록. 이전 제출·결과는 덮어쓰지 않음) |

세션 전체를 `ckad grade`로 제출한 뒤(모의시험 포함):

| 상황 | 명령 |
| --- | --- |
| ERROR가 났고 답안은 그대로다 | `ckad grade --retry` |
| 답안을 고쳤다 | `ckad grade --resubmit` |

- 진행 중인 훈련에서 `--problem` 없이 `--retry`/`--resubmit`을 하면 거부됩니다(종료 코드 2). 답안을 고치지 않고 `ckad grade --problem Q1`만 다시 하면 기존 결과를 보여 줍니다. 결과가 확정돼 있으면 종료 코드 0이지만, ERROR 결과이면 종료 코드 3과 `채점을 확정할 수 없습니다. 사용할 수 있는 명령: ...`가 나옵니다.
- 지금 허용되는 복구 명령은 `ckad status`의 `허용되는 복구 명령:` 줄이 알려 줍니다.
- 답안이 바뀐 것이 확인되면 `--retry`는 `답안이 바뀌었거나 동일함을 확인할 수 없습니다. ckad grade --resubmit으로 새 제출을 기록하세요.`로 거부됩니다.
- 이미 제출한 세션에서 그냥 `ckad grade`를 하면 기존 결과와 다음 명령 안내가 나옵니다(`이미 제출했습니다. 기존 결과입니다...`). 결과가 확정돼 있으면 종료 코드 0, ERROR가 있거나 채점이 끝나지 않은 결과이면 추가로 `채점을 확정할 수 없습니다. 사용할 수 있는 명령: ...`(실제로 허용되는 명령만)와 종료 코드 3입니다.
- 모의시험을 제출한 뒤의 `--resubmit`은 최초 모의시험 점수를 바꾸지 않는 **복습 제출**로 기록됩니다(`복습 제출 기록입니다. 최초 모의시험 점수는 ckad review에서 별도로 확인하세요.`).
- `--retry`는 현재 실제 클러스터를 다시 검사합니다. 최초 제출 순간의 상태를 복구했다고 주장하지 않으며, 최초 제출 시각과 새 관찰 시각을 모두 보여 줍니다.

## 6. 복습

```sh
ckad review                              # 현재 세션 결과와 실패 근거
ckad review <세션 ID>                    # 지난 세션
ckad review --problem Q4                 # 문제 하나
ckad review --problem Q4 --solution      # 해설·모범 풀이 (열람 기록이 남음. --solution은 --problem과 함께)
```

순서는 실패한 요구사항 → 실제 관찰 결과 → 진단 명령·문서 → 원인 설명 → 모범 풀이입니다. 모의시험의 해설은 전체 제출을 오류 없이 채점한 뒤에만 열립니다(그 전에는 `ckad grade`를 하라는 안내가 나옵니다). 훈련에서는 사용자가 `--solution`으로 직접 열 때만 공개됩니다.

## 7. 초기화 (reset)

| 명령 | 하는 일 |
| --- | --- |
| `ckad reset --problem Q1` | 진행 중인 **훈련** 문제 하나를 초기화. 이전 풀이는 `attempt-1`에 남고 `attempt-2`가 새로 생깁니다. 모의시험 진행 중에는 거부됩니다. |
| `ckad reset` | 현재 세션을 끝내고(포기) 소유 리소스를 모두 정리. 환경 ID 입력으로 확인합니다. 끝낸 세션 뒤에 다음 학습을 시작하려면 필요합니다. |
| `ckad reset --cluster` | **노드가 실행 중이고 API가 응답하는** 전용 클러스터를 지우고 다시 만듭니다. 환경 ID 입력으로 확인하며, **현재 세션은 포기(ABANDONED) 처리**됩니다. 노드 컨테이너가 멈췄거나 클러스터가 사라졌으면 거부합니다(종료 코드 3). |
| `ckad reset --recover` | 중단된 초기화·이미지 빌드 기록을 이어서 정리합니다. |

`ckad reset`은 다음과 같이 묻습니다. 환경 ID는 `ckad doctor`의 첫 줄(`전용 환경: ...`)이나 이 안내에 나옵니다. 입력이 다르면 `확인이 일치하지 않아 초기화하지 않았습니다.`(종료 코드 2)로 아무것도 지우지 않습니다.

```text
세션 <세션 ID>를 포기하고 환경 <환경 ID>의 소유 리소스를 정리합니다. 풀이·성적·개인 설정은 보존됩니다.
확인하려면 환경 ID를 입력하세요:
```

- 보존: 이전 풀이 폴더, 점수, 개인 설정(`.bashrc` 등). 정리: JunKloud가 만들고 소유를 기록한 namespace·클러스터 객체·이미지. 소유하지 않은 대상과 다른 Docker 리소스는 건드리지 않습니다.
- namespace 삭제 완료를 확인한 뒤 새로 만듭니다. 정리가 안 되면 오류와 남은 대상을 보여 주며 finalizer를 무조건 제거하지 않습니다.
- 일반 `docker build`로 만든 이미지는 소유가 기록되지 않아 자동으로 지워지지 않습니다. 직접 삭제한 뒤 `ckad reset --recover`를 쓰세요.

## 8. 오답 재도전

```sh
ckad start --retry <세션 ID> --failed              # 같은 문제 version·조건
ckad start --retry <세션 ID> --failed --new-seed   # 검증된 범위의 새 조건
```

- 원본 세션은 채점이 끝났거나(COMPLETED) 포기한(ABANDONED) 상태여야 하고, 같은 namespace를 쓰므로 먼저 `ckad reset`으로 정리해야 합니다. 정리하지 않으면 `이전 학습 리소스가 남아 있습니다...`로 거부됩니다.
- 재도전 대상은 가장 최근 채점에서 FAIL이 있는 1~20문제입니다. ERROR만 난 문제는 약점으로 분류하지 않습니다. 해설을 열람한 이력은 남습니다.
- 원래 문제 패키지가 없어졌으면 다른 버전으로 몰래 대체하지 않고 `기록된 문제 패키지가 없거나 손상되어 정확히 재현할 수 없습니다...`로 거부합니다.
- `--retry`는 `--failed`와 함께 써야 하며 `--mode`, `--count`, `--domain`, `--difficulty`, `--tag`, `--seed`, `mock-id`와는 함께 쓸 수 없습니다(`재도전은 start --retry <session-id> --failed [--new-seed]로 요청하세요.`, 종료 코드 2). `--failed`와 `--new-seed`는 `--retry` 없이는 쓸 수 없습니다.
- 재도전은 `practice`/`mock`과 구별되는 별도 모드(`retry`)의 새 세션입니다. 진행 중 문제별 채점·reset이 훈련과 같은지는 이 문서에서 보증하지 않으니 `ckad status`와 `--help`를 확인하세요.

## 9. 오류 복구

| 증상 | 조치 |
| --- | --- |
| 명령이 중단됐다(터미널 종료, `Ctrl+C`, 재부팅) | `ckad status`가 미완료 작업을 `미완료 작업: ...`과 `허용되는 복구 명령: ...`으로 알려 줍니다. 안내된 명령을 실행하세요. 준비가 강제로 끊긴 경우에도 이 두 줄(`... \| setup-applied`, `허용되는 복구 명령: ckad reset`)이 먼저 나온 뒤 종료 코드 3과 `이전 준비가 중단되었습니다...` 메시지가 나옵니다. |
| `초기화가 중단되었습니다...` | `ckad status` 확인 후 `ckad reset --recover`. 이 상태에서는 새 학습을 시작할 수 없습니다. |
| 채점이 중단됐다 (`Ctrl+C` 등). 다음 `ckad grade`는 `채점을 확정할 수 없습니다. 사용할 수 있는 명령: ckad grade --retry / ckad grade --resubmit`(종료 코드 3). 제출만 기록되고 채점이 시작되지 못했다면 `이전 채점이 중단되었습니다. ckad grade --retry 또는 수정 후 --resubmit으로 복구하세요.` | 답안을 고치지 않았다면 `ckad grade --retry`(훈련 문제 하나는 `--problem Q1 --retry`), 고쳤다면 `--resubmit`(훈련 문제 하나는 `ckad grade --problem Q1`). 정확한 명령은 `ckad status`의 `허용되는 복구 명령:`을 따르세요. |
| 채점 결과에 ERROR | `ckad doctor` → 답안 그대로면 `--retry`(훈련 문제 하나는 `--problem Q1 --retry`), 고쳤으면 새 제출(`--resubmit`, 훈련 문제 하나는 `ckad grade --problem Q1`). |
| 클러스터 응답 없음 | `ckad doctor`. 노드 컨테이너가 멈췄으면(`docker ps -a --filter name=junkloud-`) `docker start`나 Docker Desktop 재시작. 노드가 실행 중인데 환경이 꼬였으면 `ckad reset --cluster`(세션 포기). 클러스터 자체가 삭제됐으면 제품 안에서 복구할 수 없습니다(누락된 클러스터·namespace를 자동으로 새로 만들지 않음). [README 8장](../../README.md#8-자주-겪는-문제와-해결)과 2.6의 전체 초기화를 보세요. |
| `이전 준비가 중단되었습니다. 풀이와 기록을 보존했습니다. ckad reset으로 정리한 뒤 다시 시작하세요.` (`ckad status`, 종료 코드 3. `ckad start`도 같은 뜻으로 `... ckad status 확인 후 ckad reset으로 정리하고 다시 시작하세요.`와 종료 코드 3으로 거부) | 준비 중이던 `ckad start`가 강제로 끊겼습니다. 이어서 준비하지 않습니다. `ckad reset`으로 정리한 뒤 `ckad start`를 처음부터 다시 하세요. 풀이와 기록은 보존되고 사라진 리소스를 자동으로 다시 만들지 않습니다. |
| `준비에 실패했습니다. 풀이와 기록을 보존했습니다. ckad reset으로 정리한 뒤 다시 시작하세요.` (`ckad status`, 종료 코드 3) | 준비가 오류로 끝났습니다. 준비 중 `Ctrl+C`도 이렇게 기록됩니다. 위와 같이 `ckad reset` 후 다시 시작하세요. |
| `준비가 진행 중입니다 (다른 터미널의 명령이 끝날 때까지 기다리세요): ...` (`ckad status`, 종료 코드 0) | 오류가 아닙니다. 다른 터미널의 `ckad start`가 준비를 진행하는 중입니다. 끝날 때까지 기다리세요. `ckad status`는 잠금을 읽기 전용으로 잠깐 확인할 뿐 잠금 파일을 만들거나 쓰지 않습니다. 그 터미널이 `[yes/no]` 질문에서 기다리는 동안에는 잠금이 풀려 있어 인자 없는 `ckad start`가 같은 확인으로 이어지고, 인자를 준 `ckad start`는 종료 코드 2로 거부됩니다. |
| `다른 준비·채점·검증 작업이 실행 중입니다...` (종료 코드 3) | 다른 터미널의 작업이 끝난 뒤 다시 시도. 다른 터미널이 준비 중일 때 `ckad start`를 해도 이 메시지로 거부됩니다. `ckad status`는 언제든 조회할 수 있습니다. |
